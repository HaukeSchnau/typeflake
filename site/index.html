Nix modules in TypeScript, typed by your own flake.

Typeflake reads the options your NixOS, nix-darwin and Home Manager configurations have and turns them into TypeScript types. You write modules against those types, and Typeflake renders each one to a plain .nix file that builds with Nix alone.

How it works

Your flake stays the build. Typeflake writes .nix files and reads the option tree back, so the types follow nixpkgs, Home Manager, nix-darwin and your own options at the versions flake.lock pins.

  1. Render the modules

    Each *.nix.ts file renders to the .nix file next to it. flake.nix imports those like any other module.

  2. Probe the configurations

    A Nix expression walks each configuration's options with builtins only, and Typeflake turns them into declarations in .typeflake/.

  3. Check

    With .typeflake/*.ts in your tsconfig, the editor completes every option and shows its description on hover.

  4. Build with Nix

    The rendered files are ordinary Nix. Delete the .ts files and the flake still builds, with no Node and no Typeflake library.

What it promises

  • Nix stays the build

    Generated Nix needs nothing but Nix. Typeflake is a way to write .nix files, not a runtime.

  • Types come from your flake

    They are probed from the configurations you already have, third-party modules and your own options included. There is no hand-written schema to fall behind nixpkgs.

  • No any

    Every expression has the type of the value it evaluates to, Nix<T>. An option type Typeflake can't map yet stays visible as Unsupported<"name">.

  • A port changes nothing

    Moving a module to TypeScript leaves every host's system.build.toplevel.drvPath as it was. Compare the two before you commit.

Get started

Typeflake needs Node 24 or newer, Nix with flakes, and a flake with NixOS, nix-darwin or Home Manager configurations. Start with one module.

Then add the generated declarations to tsconfig.json, and run typeflake render --check in CI so the .nix files never fall behind their modules.

Where it stands

Early alpha. The pieces work end to end, and the API will still change before 1.0.

Works today

  • Probing NixOS and nix-darwin configurations, with Home Manager's options through the NixOS one. The largest configuration tried so far has 41,038 options and takes 11 seconds.
  • typeflake types for options and package names, and typeflake render, with --check for CI.
  • NixOS.module, Darwin.module, HomeManager.module, define, mkIf and the other overrides, Options, nix`…` and typed lib helpers.
  • A module ported from a production flake builds the same drvPath as the original on NixOS and nix-darwin.

Next

  • Probe again by itself when flake.lock changes.
  • Types for more of lib and for package sets like python3Packages.
  • Modules shared between NixOS and nix-darwin.
